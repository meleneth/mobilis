# Galactic Exchange

This project was generated by Mobilis. Docker Compose, the service source,
database migrations, and the verification script run without Mobilis installed.

From the generated `generate/` directory, run `python3 verify-galactic-exchange.py`.
It starts the development Compose stack, sends six deterministic bilateral trade
commands, verifies broker acknowledgments and execution IDs, pauses and resumes
the portfolio consumer, replays the retained execution log into an empty second
PostgreSQL database with a new group, and injects a duplicate execution.

The event log runs on three KRaft brokers with three replicas per topic and
minimum in-sync replicas of two. The verifier stops one broker and confirms
new commands still receive acknowledgments before restarting it.
`exchange.commands` and `exchange.executions` each have five partitions. The
commodity is the key on both topics. Every command for one commodity reaches
one partition and is handled in that partition's offset order. No total order
exists across commodities. The matching engine executes each bilateral command
once per input record; it does not implement an order book. Broker redelivery
can create duplicate execution records with the same deterministic execution ID.
Both projections persist processed IDs with state changes in one database
transaction. Kafka offsets commit only afterward. This is at least once
processing with idempotent database effects, not a distributed transaction or
an exactly once PostgreSQL guarantee.

Redis stores only a volume leaderboard cache. The market projection keeps the
authoritative price, volume, and trade count in PostgreSQL and rebuilds the
cache from that state. The replay uses a separate database and a fresh group;
it does not reset offsets against existing projection state.

The HTTP services emit ingress spans. Kafka helpers inject trace context on
publish and link asynchronous consumer spans to the extracted context.
PostgreSQL instrumentation is enabled where the generated language integration
supports it. Worker processes expose Prometheus counters and replay offset
gauges on port 9000 within the Compose network. Consumer lag is available via
`kafka-consumer-groups.sh --bootstrap-server events:9092 --describe --group
portfolio-v1`. The single broker exposes JMX internally; this demonstration
does not package a JMX exporter agent.

This local three-broker cluster demonstrates one-broker fault tolerance. Its
Compose volumes are durable until explicitly removed; it is not a production
security or operations configuration.
